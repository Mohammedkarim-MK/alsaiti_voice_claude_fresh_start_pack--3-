## Phase 2 — CRAWLABILITY — **DONE** (Option A, chosen by MK)

Shipped in `ffa08ae`. Live and verified:

| URL | HTTP | `<html>` | Crawlable text | Headings |
|---|---|---|---|---|
| `/` | 200 | `lang="en" dir="ltr"` | 3,870 chars | 10 |
| `/es/` | 200 | `lang="es" dir="ltr"` | 4,787 chars | 10 |
| `/ar/` | 200 | `lang="ar" dir="rtl"` | 3,843 chars | 10 |

**How it works:** `tools/prerender.js` runs the app's own `landing()` under jsdom per locale
and injects the result between `<!--PRERENDER:START-->` / `<!--PRERENDER:END-->` in `#root`
(`docs/index.html:1343`). Output is committed, so Cloudflare Pages needs **no build command
and no config change**, and a broken generator leaves the last good HTML live.

**To regenerate after ANY edit to `docs/index.html`:**
```
node tools/prerender.js
```
`tests/prerender.test.js` (56 assertions) and a CI step fail if you forget.

**Source changes:** `docs/index.html` — locale-meta markers (`:13`), prerender markers
(`:1343`), locale read from path (`:1365`), `setLang()` updates the URL via `replaceState`
(`:1601`).

**Bug caught during build, worth remembering:** the generator worked exactly once.
`docs/index.html` is both source and English output, so run two reads back run one's output;
the literal match for `<html lang="en">` no longer existed and Arabic silently inherited
`lang="en" dir="ltr"`. Now matches the whole tag, verified idempotent over three runs.

## Phase 4 — META AND SOCIAL — **DONE** (`ffa08ae` + `4eb3372`)

Most of it shipped with Phase 2, because none of it was possible without per-locale URLs.

Per locale, per file: `canonical`, `og:url`/`type`/`locale`/`site_name`/`title`/`description`,
`og:locale:alternate` ×2, `twitter:card` (`summary_large_image`), `twitter:title`/`description`,
and the `hreflang` trio plus `x-default`. Descriptions and titles genuinely translated.

Then in `4eb3372`: `og:image` + `twitter:image`, `sitemap.xml`, `robots.txt`. All three live
and serving correct content types (`text/plain`, `application/xml`, `image/png`).

`sitemap.xml` and `robots.txt` are **generated by `tools/prerender.js`** from the same
`LOCALES` object as the pages — adding a fourth language means editing one object, not four
files. Our `robots.txt` replaces Cloudflare's default, which was `text/html` with no
`Sitemap:` line.

### og:image — action for MK
`docs/og-image.png` (1200×630, `#123A2C`, wordmark) is a **placeholder**, generated by
`python tools/make-og-image.py`. **To replace: drop your own 1200×630 PNG at
`docs/og-image.png`.** Keep those dimensions — every platform crops to them.

**It says "Arabic" in Latin script, not "العربية", deliberately.** `PIL.features.check('raqm')`
is `False` on this machine, so Pillow falls back to the BASIC layout engine and renders Arabic
as isolated, unjoined letters in logical rather than visual order — unreadable to an Arabic
reader, on the one image whose job is to advertise Arabic support. Native names need
`arabic-reshaper` + `python-bidi` (small, pure-Python) or a Pillow built with raqm.
**Not added — new dependencies get asked about first.** MK's call.

**Done:**

## Phase 5 — PART 2 DONE (`d927841`)

- **Directional icons now mirror in RTL.** They did not before — the arrow path
  `M5 12h14M13 6l6 6-6 6` rendered `transform:none` at `dir=rtl`, pointing backwards to an
  Arabic reader. `icon()` tags 8 directional names with `.ic-dir`; object icons (phone, mail,
  clock) are deliberately excluded. Verified in-browser: 1 mirrored, 37 untouched.
- **Positioning sweep finished.** My "~19 rules" estimate was wrong — most `left:`/`right:` are
  centering or symmetric and carry no direction. Only 4 were directional. 2 overrides deleted,
  2 reduced to what logic cannot express (`translateX`, `border-radius`).
- **`.field` inputs got a focus ring** to match `.form2`.

### Correction worth keeping
I reported "9 of 12 focusable elements have no visible focus indicator". **That was wrong.**
The probe called `.focus()` and read `outline` — but `:focus-visible` does not match
programmatic focus, and the page was not the active document, so it measured nothing. Re-tested
with a real Tab keypress: buttons already had an outline, `.form2` inputs already had a ring.
Focus was never broken. Outline is not the only way to draw focus, and a browser is not a DOM.
